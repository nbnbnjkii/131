# Загрузка квартала GLB/glTF (Android 0.5)

## Исправление спавна и машина (0.5)

- `LevelPlacement.h` ищет крупнейшую связную область с учётом габарита игрока на навигационной сетке 0,25 м. Старый алгоритм проверял только соседние клетки и мог выбирать изолированное пространство за забором.
- Старт выбирается с предпочтением передней части улицы `(0, 28)` и свободной областью 3×3 м вокруг центра. При недостатке места допускается меньший запас. Для текущего города без построек координаты получились примерно **X=0,614; Z=31,625** вместо прежних `(1,75; 11,25)`.
- Итоговая проверка в `Renderer.cpp` выполняется после загрузки города, автомобиля и сохранённых построек. Проверяется также принадлежность текущей позиции крупнейшей области после восстановления EGL-поверхности. Постройки не удаляются для освобождения спавна. Если вся подходящая область застроена, невозможность найти старт логируется, без удаления данных игрока.
- Добавлен `assets/models/crushed_sports_car.glb`, без изменения бинарных данных из пользовательского коммита `10914e67a26ac14ea6d53a0a804350fb6c312876` (исходное имя: `aiprintgen_Crushed Sports Car 3D Model-preview (1).glb`). Это 880 треугольников, один материал и одна встроенная текстура.
- `LoadOptions` разделяет загрузку уровня и отдельного предмета. Для машины используется `level=false`, `targetExtent=4.3f`, `yaw=π/2`. Она не нормализуется до 80 м и не получает собственную городскую сетку коллизий.
- Машина имеет размеры около **1,74×1,43×4,3 м** (ширина×высота×длина), стоит нижней точкой на уровне земли. Один AABB имеет реальный горизонтальный габарит кузова и ограниченную высоту **1,2 м**. Существующий 2.5D-движок учитывает X/Z, а не превращает этот AABB в высокую видимую стену.
- Парковка выбирается в основной доступной области с запасом под обход и минимум в 6 м от стартовой точки. Без построек это примерно **X=12,614; Z=15,125**. С постройками место может измениться; если места нет, машина пропускается, а город остаётся рабочим.
- `car_` загружается и рисуется отдельно от `city_`, с тем же освещением и декодером текстур. Ошибка машины не отключает город.
- Тесты проверяют отказ от спавна внутри замкнутого забора, учёт сохранённых предметов, реальные размеры машины, остановку движения у её коллайдера и сохранение не менее 85% исходной доступной области на текущем квартале после парковки.

## Подключённый файл

APK автоматически загружает:

```
app/src/main/assets/models/abandoned_city_street_for_games.glb
```

Файл взят без изменения бинарных данных из предоставленного пользователем коммита `5e0cccb9958b1bc4084fcb8c109abd2329ce7782`, исходный путь в том коммите — корень репозитория. На текущую рабочую ветку другие изменения из того коммита не переносились.

В нём 92 меша, 15 767 треугольников, 6 материалов и 8 встроенных изображений PNG/JPEG (1024×1024). Встроенные **baseColor**-текстуры применяются автоматически. Normal и metallic/roughness-карты пока не участвуют в освещении: текущий рендер остаётся Lambert + ambient/fog, не полным PBR.

При успешной загрузке примитивный квартал и его коллизии заменяются моделью. Строительство остаётся доступным. Если загрузка модели/загрузка в GPU не удалась, при обычном старте остаётся прежний тестовый квартал, а ошибка выводится в logcat с тегом `Ekron`.

## Файлы реализации

- `cpp/GltfScene.h/.cpp`: tinygltf v2.9.7, GLB/JSON glTF, разрешение внешних ресурсов, иерархия узлов, matrix/TRS, обратная транспонированная матрица нормалей, индексы u8/u16/u32, interleaved accessors, UV, материалы и генерация коллизий.
- `cpp/GltfRenderer.h/.cpp`: чтение через AAssetManager, статические VAO/VBO, sRGB-текстуры, wrapping, mipmaps, alpha mask/blend и освобождение GL-ресурсов.
- `cpp/ImageDecode.cpp`: единственная общая реализация stb_image, PNG + JPEG.
- `cpp/Renderer.cpp`: автоматическая загрузка и отрисовка квартала, общий свет/туман, сохранение построек отдельно от старого уровня.
- `cpp/third_party/tiny_gltf.h`, `json.hpp`: vendored tinygltf v2.9.7 и его nlohmann/json. Лицензии MIT сохранены в файлах. stb_image содержит собственную MIT/public-domain лицензию.

Геометрия загружается один раз в статические VBO, не пересобирается каждый кадр. После передачи в GPU CPU-копии вершин и изображений освобождаются. Изображения ограничиваются 2048 пикселями по каждой оси; невалидные изображения заменяются белыми.

## Внешние PNG

### Для текущего GLB, без редактирования бинарного файла

Можно добавить PNG-переопределения по индексу материала:

```
assets/models/abandoned_city_street_for_games.glb
assets/models/overrides/material_0.png
assets/models/overrides/material_1.png
...
assets/models/overrides/material_5.png
```

Это необязательные файлы: при отсутствии используется материал из GLB. Исходные UV сохраняются, текстура не генерирует новые UV. `baseColorFactor` материала умножается на текстуру; для чёрного материала фактор также надо изменить в исходной модели. Ошибочная PNG-подмена даёт белую запасную текстуру с предупреждением.

### Для JSON glTF с отдельными ресурсами

Положите `.gltf`, `.bin` и изображения в assets, сохранив относительные пути, и измените путь `city_.load(...)` в `Renderer.cpp` на ваш `.gltf`:

```
assets/models/street/scene.gltf
assets/models/street/scene.bin
assets/models/street/textures/wall.png
```

Пример соответствующих секций glTF (не полный файл):

```json
{
  "images": [{"uri": "textures/wall.png"}],
  "textures": [{"source": 0}],
  "materials": [{
    "pbrMetallicRoughness": {
      "baseColorTexture": {"index": 0, "texCoord": 0},
      "baseColorFactor": [1, 1, 1, 1]
    }
  }]
}
```

У primitive должен быть `"material": 0` и атрибут `TEXCOORD_0`. Относительные URI разрешаются через APK assets; интернет, абсолютные пути и выход через `..` запрещены. Для внешних ресурсов не забудьте включить все файлы в APK.

## Масштаб, старт и коллизии

1. Все node transforms запекаются в вершины; учитываются вложенные узлы и отражённые масштабы.
2. Горизонтальный габарит сцены нормализуется до 80 игровых метров и центрируется. Это явное решение для прототипа, а не сохранение авторского масштаба.
3. Высота земли оценивается по площади горизонтальных треугольников, а не по самому нижнему обломку.
4. Геометрия стен в диапазоне высоты игрока проецируется на сетку **0,5 м**. Проверка triangle/cell SAT избегает одного огромного AABB на весь квартал.
5. Занятые клетки объединяются по строкам в AABB, используемые существующим `World::blocked`. Неподдерживаемая землёй область также блокируется. Для этого файла получилось 1 073 полосы-коллайдера.
6. Стартовая точка выбирается на земле, в свободном участке с запасом вокруг капсулы. Локальный тест проверяет, что игрок не появляется внутри коллайдера.

Это приближённые **2.5D** коллизии для ходьбы на одном уровне, не полноценная физика треугольного меша. Узкие проходы могут сужаться из-за сетки. Нет лестниц, переменной высоты опоры, второго этажа, прыжков и точной коллизии отдельных наклонных поверхностей. Не каждый нарисованный дверной проём обязательно проходим: это зависит от геометрии модели. Нужна проверка на телефоне и, при необходимости, ручная разметка коллизий.

Постройки GLB-уровня сохраняются в `files/city-glb-v1.txt`; прежний `sandbox-v1.txt` не удаляется и не переносится автоматически в другую систему координат.

## Границы загрузчика и проверки

Поддерживается статическая геометрия TRIANGLES, обычные (не sparse) accessors, UV0, baseColorFactor/baseColorTexture, opaque/mask/blend. Анимации, skinned meshes, morph targets, Draco/Meshopt/KTX2 и required extensions не поддерживаются. Скиннинг и обязательные расширения отвергаются с диагностикой; анимация/морфинг не проигрываются. Прозрачные меши сортируются по центру в горизонтальной плоскости — возможны артефакты пересекающейся прозрачности. Culling отключён, в том числе для двусторонних фасадов.

```sh
# Из корня репозитория, без Android SDK
g++ -std=c++17 -O1 -Wall -Wextra -Werror -pedantic \
  tests/native/gltf_scene_test.cpp \
  sys/android/app/src/main/cpp/GltfScene.cpp \
  sys/android/app/src/main/cpp/ImageDecode.cpp -o /tmp/ekron-gltf-test
/tmp/ekron-gltf-test
```

Тест действительно читает предоставленный GLB: проверяет количество мешей/материалов, декодирование всех встроенных PNG/JPEG и свободную стартовую точку. Отдельный синтетический JSON glTF проверяет внешний `.bin`, node TRS и вычисление отсутствующих нормалей. CI также собирает APK и проверяет шейдеры. Успешная компиляция не заменяет визуальную проверку на устройстве.
